# Урок 04 — Профіль користувача і безпечне редагування акаунта

## Що ми додали

Користувач може змінювати свої базові дані через settings/profile API.

Основна ідея: frontend надсилає тільки дозволені поля, а backend перевіряє DTO перед записом у БД.

## DTO

**DTO (Data Transfer Object)** — опис того, які дані дозволено прийняти в HTTP-запиті.

Наприклад, для профілю можна дозволити:

```text
firstName
lastName
```

але не дозволяти клієнту довільно прислати:

```text
role = owner
passwordHash = ...
```

## Validation

NestJS + `class-validator` перевіряють дані до business logic.

Приклад:

```text
email має бути email
ім'я не повинно бути порожнім
```

Неправильний request отримує `400 Bad Request`.

## Чому це важливо

Ми не довіряємо даним із браузера. Навіть якщо UI не показує поле, користувач може вручну сформувати HTTP request.

## Що сказати на співбесіді

> Input validation виконується на API-рівні через DTO, а не тільки через HTML/React форму.
